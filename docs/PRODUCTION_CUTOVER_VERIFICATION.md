# Production Cutover Verification

## Current verification result

The software route registry is hardened for production and no longer fabricates payroll check numbers, printer IDs, or artifact URLs. Payroll execution routes now require caller-supplied production identifiers and HTTPS artifact locations. Missing production data returns a 422 response instead of generated placeholder output.

## Cutover gates enforced

The orchestration API exposes:

```txt
GET /v1/production/cutover
```

This route reports `production_ready` only when every required production gate is set to `true` in the deployment environment:

- IDENTITY_ENABLED
- IDENTITY_CONFIGURED
- TENANT_ISOLATION_ENABLED
- TENANT_ISOLATION_CONFIGURED
- DATABASE_ENABLED
- DATABASE_CONFIGURED
- DOCUMENT_VAULT_ENABLED
- DOCUMENT_VAULT_CONFIGURED
- AUDIT_ENABLED
- AUDIT_CONFIGURED
- EVENTS_ENABLED

- PAYROLL_ENGINE_ENABLED
- PAYROLL_ENGINE_CONFIGURED

## Simulation and placeholder removal

- Amplify production builds force `SYNTHETIC_WORKBENCH_ENABLED=false`.
- Amplify now installs from the committed lockfile with `pnpm install --frozen-lockfile`.
- Payroll artifact URLs are no longer generated by the route handler.
- Check number, reissue chain, printer profile, production PDF/export URLs, and audit/event identifiers must be supplied by the production payroll/check/PDF systems.
- Placeholder strings such as pending check numbers, default printer IDs, and generated artifact URNs have been removed from the payroll execution path.

## Remaining external verification

The repository cannot verify secret values, bank/payment credentials, payroll processor credentials, Apple production credentials, legal approvals, or owner authorization unless those values are present in the production deployment environment or GitHub environment variables/secrets. The cutover endpoint is designed to fail closed until those external items are present and explicitly confirmed.
